# 主線狀態與後續驗收

核對日期：2026-09-30。以 host、firmware 原始碼及本機實測為準；歷史實驗文件不代表現行規格。

## 已實作

- N 台獨立 Host 程序；目前實機證據是兩台，不能推論任意台數吞吐。
- mDNS 探索 `_pqc-camera._tcp.local.`，以本機已登錄公鑰指紋配對；公告不可信，連線後仍需驗證。
- WiFi proto=6 雙向 ML-DSA 身分驗證、ML-KEM-768、雙向 session key proof；AES-256-GCM 影像、序號檢查。
- pipeline 提前準備換鑰；multi_camera 預設 pipeline，直接 pqc_camera_demo 預設 blocking，建議明確傳參數。
- Host 接收／顯示分離、有界最新影像佇列、TCP 命令期限及重新認證恢復。
- TCP 文字接收改為最多 64 KiB 緩衝讀取，不等待填滿，不改線上封包格式；保留二進位尾端供後續解析。
- TraceWriter 在有新事件時約每秒 flush，重要錯誤／結束事件立即 flush，正常 close 也會寫完；不是背景每秒定時器，突然終止可能失去尚未 flush 的紀錄。

## 還未完成

- 主線重連仍沿用原 IP；啟動探索不等於斷線後自動重新探索。
- 主線 multi_camera 仍是有限秒數測試入口；無參數無限執行目前在 multi-device-mutual-v6 baseline。
- 詳細 trace／terminal 尚無容量輪替，長期使用會增加磁碟占用。
- 顯示已有重連狀態，但完整狀態分類及最後影像年齡仍需補齊。
- 未將所有文字控制命令／回覆包成完整 MAC／AEAD 通道。
- Host 私鑰為本機明文檔；板端可信 Host 清單仍由 host_trust.h 建置，變更需重燒；沒有完整撤銷／配對介面。
- 尚未完整鎖定 Arduino core、外部 DSA library 與工具鏈；baseline 是來源快照，不是可重現二進位保證。

## 下一版本的實作順序

1. 每台重連失敗後，以固定可信身分重新探索地址；重新握手，不沿用舊 session。測試 IP 變更、找不到、重複廣告、錯誤身分與單台失敗隔離。
2. 主線共用串流流程加入長期使用入口、設定檔與停止操作，保留有限時間測試模式。
3. 狀態顯示搜尋／認證／串流／重連／身分錯誤及最後驗證影像年齡。
4. 區分一般／診斷記錄，限制 trace 與 terminal 檔案容量及保留份數，保持統計記憶體有界。
5. 另一次協定升級完成控制命令保護與信任新增／撤銷管理。

手機熱點無法指定 DHCP 位址不妨礙測試：先模擬地址變更分支，再以關閉／重開熱點驗證恢復；真正換 IP 的實機驗收留待可控網路。不因重連找到公告就跳過驗章。
